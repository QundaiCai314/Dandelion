# 商业链路模型与评分细则 Framework & Scoring

## 两种模式下的证据含义 Evidence in Two Modes
- 项目检查（他人项目）：证据 = 公开材料。公开材料里没有 → 标「证据不足」，该环节最高 3 分；报告不得把「没公开」当「没做」。
- 自检（自己项目）：证据 = 创造者的回答。答不出、没验证过 = 真实的薄弱/断裂信号，按正常规则打分。

## 链路模型（6 环节）
真实需求 → 价值主张 → 获客 → 付费转化 → 交付与体验 → 复购与传播

参考框架（仅用于补充判断要点，不改变本模型）：
- 精益画布：Problem, Customer Segments, Value Proposition, Channels, Revenue Streams, Unfair Advantage
- 商业模式画布：Revenue Streams, Customer Relationships, Key Resources
- AARRR：Acquisition, Activation, Retention, Revenue, Referral
- 增长飞轮：留存-推荐-复购 的自我强化循环

## 自检提问清单 Self-Check Questions
自检模式（或项目检查中确认是自己的项目后）按环节提问，默认一次一个问题；答不上来就记为「未验证/未设计」并继续。

### 1. 真实需求 Real Demand
- 你的目标用户是谁？请具体到人群和场景。
- 他们现在怎么解决这个问题？痛有多频繁、多强烈？
- 你访谈/调研过几个真实用户？他们怎么说的？
- 他们愿意为「解决这个问题」付费吗？验证过吗？
- 市场有多大？替代方案和竞争对手有哪些？

### 2. 价值主张 Value Proposition
- 一句话说清：为谁、解决什么、为什么是你？
- 相比现有方案（包括「什么都不做」），你的独特优势是什么？
- 用户 30 秒内能感知价值吗？
- 你有什么别人不易抄走的东西（技术、资源、渠道、数据、网络效应）？

### 3. 获客 Acquisition
- 第一批用户从哪里来？具体渠道是什么？
- 渠道能规模化吗？获客成本（CAC）估算过吗？
- 有落地页 / 试用入口吗？从知道到用上的路径通了吗？
- 获客方式适合你的产品形态吗（PLG / SLG / 渠道合作）？

### 4. 付费转化 Conversion & Monetization
- 定价与商业模式定了吗（订阅 / 买断 / 免费增值 / 按用量）？
- 免费与付费的边界在哪？用户为什么升级？
- 付费入口与支付流程设计好了吗？
- 有付费意愿的证据吗（waitlist、预购、已有付费用户、对标价格）？
- 单位经济算过吗（LTV/CAC、毛利率）？

### 5. 交付与体验 Delivery & Activation
- 用户第一次使用后，多久能感受到核心价值（Aha moment）？
- 新手引导 / 模板有吗？
- 激活指标定义了吗？现在数值是多少？
- 客服 / FAQ / 故障响应怎么安排？

### 6. 复购与传播 Retention & Referral
- 什么机制让用户回来（内容更新、习惯循环、续费提醒、会员体系）？
- 什么机制让用户帮你传播（推荐奖励、可炫耀点、分享路径）？
- 流失预警和召回怎么做？
- 留存指标定义了吗（留存率、复购率、NPS）？

## 打分细则（每环节 0-10 分）
- 9-10 健康强闭环：有明确证据（数据/用户/收入）且设计与执行到位
- 7-8 基本打通：设计清晰、有部分证据、可执行
- 5-6 薄弱：有想法或有设计，但证据不足或明显短板
- 3-4 仅有想法：无设计或无证据
- 0-2 缺失：该环节完全没有信息或设计

证据不足时最高给 3 分，并在报告中列出需补充的信息。

## 每环节检查项

### 1. 真实需求 Real Demand（最难判断 → 要求严格证据）
- 目标用户是否具体（细分人群 + 使用场景）？
- 痛点是否真实、频繁、强烈？有无用户访谈 / 调研 / 社区反馈 / 数据佐证？
- 是否区分「想要」与「愿意付费解决」？
- 是否了解市场容量与竞争格局（TAM/SAM、替代方案）？
- 参考：精益画布 Problem / Customer Segments

### 2. 价值主张 Value Proposition
- 能否一句话说清「为谁、解决什么、为什么是你」？
- 与替代方案（包括「什么都不做」）相比是否有独特优势？
- 用户能否在 30 秒内感知价值？
- 是否有不公平优势（技术、资源、渠道、网络效应、数据）？
- 参考：精益画布 Value Proposition / Unfair Advantage；价值主张画布

### 3. 获客 Acquisition
- 主获客渠道是否明确，且与目标用户匹配？
- 渠道是否可规模化？获客成本（CAC）有无估算？
- 有无落地页 / 试用入口 / 激活路径？
- 是否考虑 PLG / SLG / 混合策略？
- 参考：AARRR Acquisition；精益画布 Channels

### 4. 付费转化 Conversion & Monetization（最难判断 → 要求严格证据）
- 定价与商业模式是否明确（订阅 / 买断 / 免费增值 / 按用量）？
- 免费与付费边界是否清晰、升级理由是否充分？
- 转化路径有无明确的付费触点？支付流程是否顺畅？
- 有无付费意愿证据（waitlist、预购、已有付费用户、对标价格）？
- 单位经济是否测算过（LTV/CAC、毛利率）？
- 参考：商业模式画布 Revenue Streams；AARRR Revenue

### 5. 交付与体验 Delivery & Activation
- 核心价值能否在首次使用后快速兑现（Aha moment）？
- 上手引导 / 模板是否降低学习成本？
- 有无激活指标定义与监控？
- 服务与支持（客服、FAQ、故障响应）是否到位？
- 参考：AARRR Activation

### 6. 复购与传播 Retention & Referral（最容易断 → 无设计即断裂）
- 有无留存机制（内容更新、习惯循环、续费提醒、会员体系）？
- 有无传播设计（推荐奖励、分享动机、可炫耀点、社交传播路径）？
- 有无流失预警与召回路径？
- 是否定义留存指标（留存率、复购率、NPS）？
- 参考：AARRR Retention / Referral；增长飞轮

## 判定规则
- 单环节：7 分及以上 = 健康；5-6.9 = 薄弱；低于 5 = 断裂。
- 总体结论：
  - 链路打通：全部环节 ≥7 且平均分 ≥7.5
  - 接近打通：无环节低于 5，平均分 ≥7，但存在低于 7 的环节
  - 未打通：任一环节低于 5，或平均分低于 7
- 他人项目：结论前注明「基于公开证据」，低分环节标注「证据不足」或「设计缺失」。
- 行动优先级：断裂环节（分数低者先）→ 薄弱环节（分数低者先）→ 若全部健康，优先寻找复购与传播的增长杠杆。

## 修复模式工作法 Repair Mode
修复按「断裂 → 薄弱 → 增长杠杆」顺序逐项进行。AI 不直接修改用户产品，而是为每项输出**完整修改方案**：目标 → 具体改动 → 实施步骤 → 验收标准；用户确认后自行执行，执行完成可要求复检。
各环节常见修复杠杆（作为方案内容素材）：
- 真实需求：用户访谈提纲（5-8 问）、最小付费意愿验证（waitlist/预售）、替代方案调研清单
- 价值主张：一句话价值主张模板（为谁/解决什么/为什么是你）、落地页首屏文案、与替代方案对比表
- 获客：种子用户获取计划（渠道 + 话术 + 数量目标）、落地页结构、内容选题清单
- 付费转化：3 档定价方案、免费/付费边界定义、支付流程清单、LTV/CAC 测算表
- 交付与体验：激活路径设计（3 步内兑现核心价值）、新手引导文案、激活指标定义
- 复购传播：留存机制设计（习惯循环/内容更新/续费提醒）、推荐奖励方案、流失召回路径

## 复检规则 Re-check
用户可随时要求「复检」：用当前证据重新逐环节打分，对比上次分数，更新结论与剩余行动。
复检输出：分数对比表（上次/本次/变化）+ 更新后的结论 + 剩余行动。分数提升说明修复有效；未提升的环节继续进入修复队列。
